# ADR-003. Разделение data-plane и control-plane

**Статус:** принято · **Разделы:** §3.1, §3.1.1

## Контекст

Гейтвею нужны конфигурация, квоты, реестр моделей и политики. Наивное
решение — читать их из базы по мере надобности.

## Решение

Два слоя. Control-plane владеет конфигурацией и кладёт её в память
data-plane. Горячий путь читает только память, **ноль сетевых вызовов**.

## Почему

Поход в базу за конфигом на каждом запросе — это и латентность в горячем
пути, и точка отказа: недоступность базы означала бы остановку трафика.

## Последствия

- Падение control-plane не останавливает трафик: data-plane работает на
  последнем известном конфиге.
- Модель добавляется правкой YAML без передеплоя — прямой ответ на
  критерий «гибкость», демонстрируемый в прямом эфире за 2,5 секунды.
- Data-plane остаётся stateless и масштабируется горизонтально.
- **Сломанный конфиг не применяется.** Гейтвей остаётся на последней
  рабочей версии и громко сообщает об ошибке. Падение из-за опечатки в
  YAML во время показа — худший исход из возможных.
