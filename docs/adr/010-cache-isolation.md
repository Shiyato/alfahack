# ADR-010. Изоляция префикс-кэша между тенантами

**Статус:** принято · **Разделы:** §3.3.6.10

## Контекст

Мы строим мультитенантный банковский прокси, а не исследовательский
стенд.

## Решение

Идентификатор тенанта входит в ключ хеширования префикса. Кросс-тенантное
переиспользование кэша запрещено.

## Почему

Совместное использование KV-кэша между тенантами — известный вектор
атаки по времени ответа: если чужой префикс уже в кэше, запрос с
угаданным префиксом обслужится заметно быстрее. Это готовый боковой
канал для выяснения содержимого чужих промптов.

## Цена

Ниже доля попаданий при большом числе мелких тенантов: общий системный
промпт, одинаковый у всех, кэшируется по разу на тенанта.

Это осознанный размен, и его стоит озвучить на защите: упоминание такого
риска отличает решение уровня «прочитал статью» от решения уровня
«понимаю, что строю для банка».

## Реализация

`block_hashes(text, block_tokens, salt=tenant_id)` — соль входит в первое
звено цепочки, поэтому расходятся все блоки, а не только первый.
Проверено тестом: одинаковый текст у разных тенантов даёт нулевое
совпадение префикса.
