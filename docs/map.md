# Карта: где что менять

Документ для работы под давлением. Отвечает на один вопрос: **«мне надо
сделать X — куда идти и что сломается»**. Для понимания «почему так»
есть [architecture.md](architecture.md) и [adr/](adr/README.md).

---

## Правило нулевое

Прежде чем править код, проверьте, не решается ли задача правкой YAML.
Конфигурация применяется за ~2,5 секунды без передеплоя, и половина
типовых изменений живёт там.

```bash
# посмотреть, что применилось
curl -s localhost:8080/admin/state | python3 -m json.tool
```

## Частые задачи

### Подключить новый апстрим

`config/models.yaml` → блок `upstreams` + запись в `models`.
Правка файла, ничего больше. Валидатор предупредит об опечатке.

### Платформа говорит на другом API

Новый адаптер: `gateway/upstream/adapter.py`, класс по образцу
`OpenAIAdapter`, регистрация в `ADAPTERS`, затем `adapter: имя` в
`config/models.yaml`.

Нужны три метода: `build_payload`, `parse_frame`, `endpoint`.

**37 контрактных тестов применятся к нему автоматически** — они
параметризованы по реестру. Запустить: `uv run pytest tests/test_contracts.py`.
Читать перед написанием адаптера не нужно, но если он их не проходит —
там написано, почему.

### Поменять стратегию маршрутизации

`config/models.yaml` → `router.strategy`. Допустимо:
`least_load`, `consistent_hash`, `session`, `dualmap`.

Новая стратегия: `gateway/router/strategies.py`, наследник
`RoutingStrategy`, регистрация в `STRATEGIES`, плюс добавить имя в
множество `known` внутри `validate()` в `gateway/core/config.py` —
иначе валидатор отвергнет конфиг как неизвестную стратегию.
Контрактные тесты применятся автоматически.

### Поменять квоты

`config/ratelimit.yaml`. **Считайте, а не назначайте**: при средней
длине запроса 8800 токенов квота «500 000 токенов/мин» даёт 0,9 запроса
в секунду. Формула записана в самом файле.

### Поменять поведение при отказах

`config/models.yaml` → блок `resilience`: пороги размыкателя, число
попыток, задержки, частота опроса апстримов.

Правила деградации — `config/fallback.yaml`.

### Поменять SLO

`config/models.yaml` → блок `slo`. Коэффициенты модели времени префилла
берутся не оттуда, а из `config/calibration.yaml`, который создаётся
замером:

```bash
PYTHONPATH=. uv run python loadtest/calibrate.py --url http://127.0.0.1:9001
```

### Добавить метрику

`gateway/telemetry/metrics.py`. Панель в
`deploy/grafana/dashboards/gateway.json`.

`tests/test_observability.py` проверяет, что каждая панель ссылается на
существующую метрику: переименование без правки дашборда роняет тест,
а не молча оставляет пустой график.

## Что легко сломать незаметно

Каждый пункт — дефект, который **уже случался** и был найден измерением,
а не чтением кода. Все закрыты тестами в `tests/test_regression.py`.

| Что | Симптом | Сторож |
|---|---|---|
| Детерминированный разрыв ничьей | 2586 запросов из 2589 на один апстрим | `test_trafik_ne_konsentriruetsya` |
| Ключ сессии, меняющийся по ходам | залипания нет вовсе | `test_klyuch_sessii_ustoichiv_po_hodam` |
| Один владелец на блок в таблице префиксов | выигрыш 1 п.п. вместо 10 | `test_distribution` |
| Изъятие чужого запроса из очереди | 14 млн отдач на 4 тыс. запросов | `test_dispetcher_ne_zavisaet` |
| Размыкание всех апстримов при общей перегрузке | 3 успешных из 2073 | `test_reestr_ne_ostavlyaet_bez_apstrimov` |
| `await` в `finally` асинхронного генератора | брошенные генерации жгут ёмкость | `test_massovye_razryvy` |
| Граница повторов на служебном кадре | деградация не срабатывает | `test_sluzhebnye_kadry` |

**Общее у всех**: результат оставался корректным, тесты вида «функция
что-то вернула» проходили. Ловится только измерением поведения —
распределения трафика, числа оборотов, занятых слотов.

## Правила, которые нельзя нарушать

Не стилистические предпочтения, а вещи, ломающие систему тихо.

**1. Повтор запроса — только до первого кадра с содержимым.**
После него стрим не идемпотентен: клиент получит склейку двух генераций.
Граница живёт в `RetryGuard`, отдельным объектом именно для того, чтобы
нарушение было заметно при чтении.

**2. Разрыв клиентом обязан отменять запрос к апстриму.**
Иначе брошенная генерация продолжает жечь ёмкость. Проявляется только
под нагрузкой, когда искать некогда.

**3. `await` в блоке `finally` асинхронного генератора ненадёжен.**
При отмене этот блок выполняется уже после возврата из `aclose()`, и
ожидание откладывается на неопределённый срок. Всё, что обязано
произойти при отмене, планируется задачей.

**4. Идентификатор тенанта входит в ключ префикса.**
Общий кэш между тенантами — боковой канал: чужой промпт угадывается по
времени ответа.

**5. Квота списывается вперёд, корректируется по факту.**
Без предварительного списания все параллельные запросы пройдут проверку
раньше, чем завершится хоть один.

**6. Метрика нагрузки считает токены, а не запросы.**
Запрос на 100k токенов и на 200 нагружают систему на два порядка
по-разному.

**7. Проба живости не зависит от апстримов.**
Иначе отказ апстрима снимет исправный экземпляр с балансировки и
превратится в отказ сервиса.

## Диагностика

```bash
curl -s localhost:8080/admin/state | python3 -m json.tool
```

| Поле | О чём говорит |
|---|---|
| `pressure` | отношение прогноза TTFT к бюджету SLO |
| `rejecting` | включён ли режим раннего отказа |
| `flips` | частые переключения под ровной нагрузкой = сломано демпфирование |
| `queue` | глубина по классам обслуживания |
| `dispatcher.spins` | много оборотов на запрос = диспетчер крутится вхолостую |
| `breakers[].open_reason` | `latency` — апстрим медленный, `consecutive` — мёртвый |
| `upstreams[].busy` | признак занятости; всё занято при пустой очереди — сломан опрос |
| `calibrated` | `false` означает, что оценки TTFT ни на чём не основаны |
| `config.failed_reloads` | конфигурация отвергнута, работаем на предыдущей |

## Быстрые проверки

```bash
uv run pytest tests/ -q                   # 209 тестов, ~8 секунд
uv run pytest tests/test_regression.py -q # только сторожа, ~1 секунда
loadtest/e2e.sh                           # 16 сквозных, нужен поднятый стенд
(cd mock-upstream && go test ./...)       # контрольные опыты мока
(cd loadtest/bench && go test ./...)      # профиль нагрузки соответствует §5.3
```

**Если замер даёт неожиданно хороший результат — сначала проверьте
прибор.** На этом проекте так было четыре раза: тёплый кэш между
прогонами, `CV = 0` от пустой системы, goodput по нагрузке в момент
приёма, модель без декодирования. Каждый раз «отличный результат»
оказывался сломанным измерением.
