# mock-upstream — управляемая заглушка LLM-апстрима

Стенд для воспроизводимой нагрузки (docs/architecture.md §5). Отдаёт
OpenAI-совместимый SSE и моделирует то, что делает настоящий движок
инференса значимым для нашей архитектуры.

## Почему на Go

Прибор обязан иметь запас по производительности относительно измеряемой
системы. Если заглушка захлебнётся раньше гейтвея, все графики будут
измерять заглушку. Отдельный процесс — значит, никакой границы внутри
горячего пути не добавляется, и выбор языка ничего не усложняет.

## Что именно моделируется

| Свойство | Как | Зачем |
|---|---|---|
| Суперлинейный префилл | `t = A + B·m + C·(m/1000)²` | внимание квадратично; линейная модель врёт на длинных контекстах |
| Префикс-кэш | блочное цепочечное хеширование, LRU + TTL | без настоящего кэша cache-aware роутинг нечем измерить |
| Ёмкость батча | семафор на `-concurrency` | иначе перегрузку не воспроизвести |
| Очередь перед батчем | счётчик `queued` | запрос, не попавший в батч, — признак занятости (§3.3.3.7) |
| Замедление от батча | `ITL·(1 + penalty·(batch−1))` | декодирование сублинейно по батчу |
| Отмена клиентом | контекст запроса | проверка на зомби-запросы (§3.3.9) |

Токен считается как 4 байта текста. Мок самосогласован: он нигде не сверяет
свою меру с чужой, поэтому точность токенизатора здесь не важна — важны
воспроизводимость и монотонность по длине.

## Запуск

```bash
go build -o mockup . && ./mockup -addr 127.0.0.1:9001
```

Полезные конфигурации:

```bash
# «Быстрый» инстанс и «медленный» — для проверки балансировки
./mockup -addr :9001 -itl 8ms  -concurrency 8
./mockup -addr :9002 -itl 25ms -concurrency 4

# Инъекция отказов для chaos-сценария (§4)
./mockup -addr :9003 -error-rate 0.3          # 30% пятисоток
./mockup -addr :9004 -overloaded              # всегда 429
./mockup -addr :9005 -hang-rate 0.2 -hang-for 60s   # зависание без единого байта
```

Зависание проверяет раздельный таймаут на TTFT: один общий таймаут такой
отказ не ловит (§3.3.8).

## Эндпоинты

| Путь | Назначение |
|---|---|
| `POST /v1/chat/completions` | OpenAI-совместимый, `stream` поддерживается |
| `GET /v1/models` | список моделей |
| `GET /healthz` | проба живости |
| `GET /state` | внутреннее состояние: `pending_prefill_tokens`, `has_pending_queue`, кэш |
| `GET /metrics` | Prometheus |

`/state` отдаёт сигналы, которые в реальности видны только у self-hosted
движка. Это сценарий 1 из §3.3.6.8. Эндпоинт держится отдельно нарочно:
его можно не использовать и честно проверить деградацию до сценария 2,
когда апстрим непрозрачен.

## Расширение контракта

`mock_output_tokens` в теле запроса жёстко задаёт длину ответа. При
воспроизведении трасс это обязательно: если длина ответа плавает, история
следующего хода перестаёт совпадать с закэшированной и паттерн
переиспользования ломается (§5.2).

## Заголовки ответа

`X-Mock-Instance`, `X-Mock-Prompt-Tokens`, `X-Mock-Cached-Blocks`,
`X-Mock-Cached-Tokens`, `X-Mock-Queue-Wait-Ms`, `X-Mock-Prefill-Ms`.

Это не декорация: по ним гейтвей сверяет собственную оценку TTFT с тем,
как апстрим устроен на самом деле. Контрольный опыт для калибровки (§3.3.6.7a).

## Тесты

```bash
go test ./...
```

Это контрольные опыты для прибора, а не проверка «нажимается ли кнопка».
Они утверждают, что наблюдаемый TTFT совпадает с формулой, что попадание в
кэш даёт ровно предсказанную экономию, что цепочечное хеширование рвётся на
расхождении истории и что отмена клиентом освобождает слот.
